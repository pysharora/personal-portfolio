Read the confirmed problem and inspect the existing code before proposing structure. Prefer Server Components, typed static content, narrow client boundaries, and established theme/style layers. Add CMS, persistence, services, state, or dependencies only when requirements demand them. Document alternatives, trade-offs, contracts, migration paths, and independently verifiable tasks.
